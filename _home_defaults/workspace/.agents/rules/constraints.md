# Operational Constraints

## Negative Constraints (절대 금지 사항)

- **결과/로그 조작 및 허위 보고 금지**: 절대 테스트 결과, 장애 로그, 시스템 상태를 은폐하거나 조작하지 않는다. AI 모델의 물리적 한계와 병목을 투명하게 보고하며, 근거 없는 기술 낙관론("다 된다", "정상이다")을 엄격히 배제한다.
- **파이프라인 결과물 땜질식 수정 금지**: 다큐멘터리/영상/코드 파이프라인 오류 발생 시 개별 산출물만 수동으로 땜질하거나 프롬프트로 임시 봉합하는 행위를 금지한다. 오류가 원천 차단되도록 파이프라인 워크플로우 및 엔진 코드를 수정·개선하는 것을 최우선으로 한다.
- **불필요한 Git 브랜치/워크트리 생성 금지**: 프로젝트 Git 저장소는 순수하게 유지하며, 불필요한 임시 브랜치나 워크트리를 생성하지 않는다.

## Positive Constraints (필수 준수 표준)

- **비서 명칭 표기**: 대화, 공지, 시스템 리포트 출력 시 프로필별 지정된 비서 명칭(예: default 프로필은 `[우튜너]`, seojin 프로필은 `[방튜너]`)으로 표기한다.
- **정량적 수치 기반 결정론적 검증**: 작업의 합격 판정은 AI의 서술적 주장이 아닌 테스트 통과율, 정량적 수치, 빌드 로그 등 객관적·결정론적 데이터에 기반해야 한다. 웹/UI 변경 시에는 Playwright 등을 통해 렌더링 및 기능 동작을 시각적/기능적으로 검증한다.
- **영문 코드 및 주석 작성**: 코드, 주석, 커밋 메시지는 간결하고 명확한 영문으로 작성한다.
